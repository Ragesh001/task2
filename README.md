# Task2 — Document Q&A System

Upload a document (PDF, DOCX, or TXT) and ask questions about its content.
Answers are generated by `openai/gpt-oss-20b`, called through the **Hugging
Face Inference API** (hosted) — no model download, no GPU needed on your
machine.

## How it works

```
Browser (upload/ask)
        │
        ▼
   Flask app (app.py)
        │
        ├─ document_reader.py  → extract text from PDF/DOCX/TXT, split into chunks
        ├─ retriever.py        → TF-IDF picks the chunks most relevant to the question
        └─ ai_engine.py        → huggingface_hub.InferenceClient sends the
                                  context + question to openai/gpt-oss-20b
                                  running on Hugging Face's servers, and
                                  returns the generated answer
```

- Documents are chunked (≈800 characters, 150 char overlap) so long files
  don't overflow the model's context window.
- When you ask a question, a TF-IDF similarity search finds the top 3
  chunks most related to your question — classic retrieval, no extra ML
  model or download involved.
- Those chunks + your question are sent as a chat-style request to
  `openai/gpt-oss-20b` via the Inference API, and the answer comes back
  over a normal HTTP call — typically a few seconds, not minutes.

## Setup

### 1. Get a Hugging Face access token
- Create a free account at https://huggingface.co if you don't have one.
- Go to https://huggingface.co/settings/tokens and create a **Read** token.
- If the model page (https://huggingface.co/openai/gpt-oss-20b) shows a
  license/agreement prompt, accept it there first — otherwise API calls
  for that model will fail with a 403.

### 2. Set the token as an environment variable

```bash
export HF_TOKEN="hf_xxxxxxxxxxxxxxxxxxxx"        # macOS/Linux
setx HF_TOKEN "hf_xxxxxxxxxxxxxxxxxxxx"           # Windows (new terminal after)
```

### 3. Install dependencies

```bash
cd Task2
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Run

```bash
python app.py
```

Then open **http://localhost:5000** in your browser.

1. Drop or select a PDF / DOCX / TXT file and click **Index document**.
2. Check the status line at the bottom of the page — it should quickly
   say "Connected" / model ready (this is just an API client init, not a
   model download, so it should be near-instant).
3. Type a question in the **Inquiry** box and hit **Ask**.
4. The model's answer, grounded in your document, appears in the chat log.

## Troubleshooting

- **"HF_TOKEN environment variable is not set"** — you skipped step 2
  above, or ran the app in a different terminal session than the one
  where you exported it.
- **403 / gated repo error** — visit the model page on huggingface.co
  while logged in and accept the license/terms if prompted.
- **Model not available via Inference API** — some very large or newly
  released models aren't always enabled for the free serverless
  Inference API and may require an Inference Endpoint (a paid, dedicated
  deployment) instead. If you hit this, check the model's page on
  Hugging Face for an "Inference Providers" panel telling you which
  providers currently host it — the error message printed in your
  terminal (from `ai_engine.py`) will include the underlying reason
  reported by Hugging Face.
- **Slow answers** — hosted inference for a 20B model still takes real
  compute time server-side; a few seconds to ~30s per answer is normal.

## Notes / next steps

- Document chunks are currently kept **in memory** (a Python dict) — restart
  the app and you lose indexed documents. Swap in a database (SQLite,
  Postgres) or a vector store if you need persistence across restarts.
- For much larger document collections, consider replacing the TF-IDF
  retriever with proper embeddings and a vector index (FAISS, Chroma, etc.)
  for better semantic retrieval.
- There's no authentication — add one before exposing this beyond localhost.
- Your `HF_TOKEN` is read from an environment variable, never hardcoded or
  sent to the browser — keep it that way, and don't commit it to version
  control.
